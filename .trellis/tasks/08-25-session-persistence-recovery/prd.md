# 会话生成与主机审批状态断线持久化及恢复

## 背景与目标
在现有架构下，当用户在 Agent 处于流式生成、思考或等待主机命令执行审批时刷新页面、关闭标签页或发生网络中断，由于消息与审批中间态仅保存在内存中或在流式结束时才落库，会导致用户重新进入或刷新页面后：
1. 前端生成的回复直接丢失；
2. 待用户批准的主机命令操作卡片消失，会话无法继续。

本需求的目标是实现 **会话生成与审批状态即时持久化及断线恢复**，确保即使页面刷新或网络重连，会话能够恢复待审批状态或查看已完成的生成内容，并提供防误触刷新拦截。

## 用户场景 (User Stories)
1. **防误触提醒**：用户在 Agent 生成中或处于待审批确认时误按刷新/关闭标签页，浏览器弹出原生确认提示，避免意外中断。
2. **待审批状态断线恢复**：Agent 触发主机危险/写操作需要审批时，后端即时将待审批状态与 `approval_id`、命令详情落库；用户刷新页面或切换会话回来后，界面能自动还原审批卡片，并允许用户继续执行「允许」或「拒绝」。
3. **后台持续生成与消息落库**：用户在流式生成中关闭网页后，后台 Agent 任务不被直接丢弃，生成完成后自动将最终消息持久化到数据库；用户下次进入会话即可直接看到完整生成内容。

## 功能需求
1. **前端页面卸载拦截**：在 `Chat.tsx` 与 `AgenticChat.tsx` 中，当 `isLoading` 或存在 `pendingApproval` 时注册 `window.addEventListener('beforeunload', ...)`。
2. **消息表（MessageRow）中间态字段支持**：支持 `status`（`pending_approval`, `done`, `failed`, `generating`）与 `metadata` 扩展存储。
3. **即时落库待审批消息**：当 `engine.py` 发送 `host_command_approval` 事件时，即时在数据库中记录一条 `role: assistant`, `status: pending_approval` 消息，包含 `approval_id`、`host_id`、`host_name`、`command`。
4. **响应审批后更新消息状态**：用户批准或拒绝后，后端更新该消息状态为已决策，并继续追加/更新后续回复。
5. **历史消息查询与前端反显**：`get_messages` 接口返回包含 `status` 和 `metadata` 的消息，前端加载历史消息时若检测到未决审批，自动渲染对应审批卡片并绑定交互。

## 验收标准 (Acceptance Criteria)
1. [ ] 在流式生成或待审批状态下刷新页面，浏览器弹出离开确认提示；
2. [ ] 在弹出审批确认时强制刷新页面，重新进入该会话后，审批卡片依然存在且可正常点击「允许执行」或「拒绝执行」；
3. [ ] 审批决策提交后，后端 Worker 正常推进并将最终回复结果保存至历史消息中；
4. [ ] 现有全部单元测试与集成测试通过。
