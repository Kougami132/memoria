Memoria 架构评审报告

深模块演进候选 (Deepening Candidates)

揭示 Memoria 运行时与 Agent 子系统中的架构摩擦、浅模块反模式以及缺失的接缝（Seams）。

评审对象: memoria-rag
架构标准: 软件设计哲学 (Philosophy of Software Design)

全景概览与代码库摩擦点分析

Memoria 已经从最初纯粹的检索引擎演进为一个支持 Web 聊天、兼容 OpenAI 协议的 API、QQ 机器人频道接入以及主机（Host）系统运维工具执行的多接入 Agentic 平台。近期代码提交的改动热点高度集中在 memoria/agents/engine.py、memoria/server/routes/openai.py、memoria/connectors/host/ 以及 memoria/storage/db.py。

候选方案 1
统一单轮会话编排器 (Unified Turn Orchestrator)
消弭分裂的双重 RAG 与 Agent 执行回路，恢复路由适配器的内聚与局部性。
候选方案 2
主机安全策略引擎 (Host Security Policy Engine)
将危险命令匹配与人工确认审批 Token 的完整生命周期收拢下沉到原子安全接缝后。
候选方案 3
统一会话存储接缝 (Unified Conversation Store Seam)
消除并行的 Standard / Agentic 会话模型，整合数据库中分裂的追踪与生命周期管理。
候选方案 01 推荐等级: 强烈推荐 (Strong)

统一单轮会话编排器：收拢割裂的双重 RAG / Agent 执行回路

所属领域: 核心编排与接入适配层 (Core Orchestration & Ingress Seams)

涉及文件与模块

memoria/agents/engine.py memoria/core/pipeline.py memoria/server/routes/openai.py memoria/server/routes/chat.py memoria/server/routes/agent_chat.py memoria/qqbot/adapter.py
核心痛点：执行回路分裂与浅适配器泄漏

代码库维护着两套分道扬镳的执行引擎：一套是 Pipeline.query()（430 行的同步单层工具循环，内嵌提示词拼装和主机工具 Schema 生成），另一套是 AgenticRagEngine.run()（1,600 行的 LangGraph 多智能体图状态机）。

由于缺乏深接缝，上游适配器（openai.py、chat.py、qqbot/adapter.py）充斥着大量的重复编排：自行查表提取上下文历史、拼装 System Prompt、手动监听流式并写回 DB 数据库记录。甚至在版本迭代中，agent_chat.py 路由在重构中被遗漏注册进 app.py，直接体现了接入层极差的局部性（Locality）。

改进构想：深编排模块与统一的单轮会话接缝

彻底弃用并移除 Pipeline.query() 中的遗留执行回路，统一下沉为一个深模块：TurnOrchestrator（或基于深化后的 AgenticRagEngine）。

该接缝对外仅暴露极简接口：run_turn() 与 stream_turn()。所有外部适配器（OpenAI 兼容协议、Web 界面、QQBot、CLI）仅需传入会话/机器人标识与用户输入。提示词构建、召回检索、工具循环分发、持久化及 SSE Chunk 生成被完整封装在内部。

局部性 (Locality)、杠杆率 (Leverage) 与测试表面
局部性 (Locality) 提示词模板解析、工具 Schema 注册、会话上下文组装以及消息持久化全部收束在单一点，不再分散飞溅在 openai.py、chat.py 和 pipeline.py 中。
杠杆率 (Leverage) 对多智能体路由逻辑、流式事件结构或错误恢复的任意一处改进，立刻自动化惠及 OpenAI 接口、Web 控制台和 QQBot，形成极高的复用杠杆。
测试表面 (Test Surface) 测试用例通过公开的单轮接缝输入真实用户消息并断言输出，无需探入内部字典结构断言中间状态，更不必针对每一个 mock 子节点做脆弱的打桩。

候选方案 02 推荐等级: 强烈推荐 (Strong)

主机安全策略引擎：封装高危正则与人工审批全生命周期

所属领域: 主机连接器与安全边界 (Host Connector & Security Boundary)

涉及文件与模块

memoria/connectors/host/guard.py memoria/connectors/host/approval.py memoria/connectors/host/connector.py memoria/agents/engine.py memoria/core/pipeline.py memoria/server/routes/hosts.py
核心痛点：安全校验飞溅散落与 Token 外部协调

执行远程主机命令当前需要调用方协同 3 个独立的浅层模块：用 CommandGuard 跑正则匹配、用 ApprovalManager 签发和核销审批 Token、再调用 HostConnector 建立 SSH 执行。

在 engine.py（500-650 行）、pipeline.py（180-230 行）以及 hosts.py 中，调用方每次都得手动读 DB 拿配置、实例化 CommandGuard、自行比对 token、更新数据库状态。外部对安全实现细节（哈希算法、危险模式分类）了解过多，模块极其浅薄。

改进构想：下沉构建 HostSecurityPolicy 深模块

将 CommandGuard 与 ApprovalManager 彻底合并，重塑为内聚且深沉的 HostSecurityPolicy 引擎。

接缝对外仅暴露原子网关方法：authorize_and_execute(host_id, command, channel_ctx, approval_token=None)。它在内部查询主机安全级别、加载动态危险模式、验证/消费审批 Token、记录审计轨迹，且仅在授权无误时透传给 SSH 执行层。

局部性 (Locality)、杠杆率 (Leverage) 与测试表面
局部性 (Locality) 安全判定、Token 签发、核销与超时清理完全内聚。Agent 执行回路无需碰触 Token 字符串细节，也不必反复写 DB 兜底逻辑。
杠杆率 (Leverage) 未来引入指令频次限流、审计留痕日志或全新的审批交互（如钉钉/企业微信审批 Webhook），无需改动 Agent 或 Pipeline 一行代码即可生效。
测试表面 (Test Surface) 测试表面极度清晰：携带合法 Token 执行 → 成功通过；无 Token 执行高危指令 → 返回待审批状态及摘要；只读模式执行 → 拒绝执行。再也不用针对内部正则字典写脆弱的单元 Mock。

候选方案 03 推荐等级: 值得探索 (Worth Exploring)

统一会话存储接缝：消除双轨会话与追踪模型

所属领域: 存储层与会话管理 (Storage & Session Management)

涉及文件与模块

memoria/storage/db.py memoria/server/routes/sessions.py memoria/server/routes/agent_sessions.py memoria/agents/engine.py
核心痛点：双轨会话类型与分裂的数据接口

数据库层针对完全同构的概念暴露了重复的 CRUD 方法： list_sessions() 对照 list_agentic_sessions()，get_session() 对照 get_agentic_session()，以及 delete_session() 对照 delete_agentic_session_messages()。

在 API 路由层同样分裂出了 /api/sessions 与 /api/agent-sessions。多步骤追踪信息（MessageTraceRow）与 Agent 会话强绑定，而普通会话则通过消息里的额外 JSON 字段打补丁，存储概念高度碎片化。

改进构想：深层 ConversationStore 统一持久化模块

在数据库底层抹平两类会话的概念割裂，提供统一的深模块接口 ConversationStore。

所有对话（直接检索回答、多智能体深度推理、或是 QQBot 交互）共享同一套 Session 实体模型，仅用引擎类型作为标记属性（type: 'standard' | 'agent'）。步骤追踪、人工审批单据与历史消息通过统一接缝操作，从 DB 类中剔除数十个冗余方法。

局部性 (Locality)、杠杆率 (Leverage) 与测试表面
局部性 (Locality) 会话全生命周期管理、消息归档清理以及级联删除逻辑全部内聚在单点，无需维护两套时刻可能脱节的清理 SQL 语句。
杠杆率 (Leverage) 前端会话侧边栏列表、筛选搜索、会话导入导出等能力对普通对话与复杂 Agent 对话天然透明适配。
测试表面 (Test Surface) 一套集中的存储集成测试即可无死角覆盖所有对话模式的持久化、回溯与级联删除特性。

首要建议先行推进的方案

候选方案 01: 统一单轮会话编排器 (Unified Turn Orchestrator) 是当前整个仓库中重构杠杆率最高的机会。

Pipeline.query() 与 AgenticRagEngine.run() 之间的割裂是导致多处逻辑重复和意外路由漂移的根因（例如 agent_chat.py 在重构时被遗落挂载到 app.py，导致 Web 与 OpenAI 协议端点完全脱节）。

一旦确立起统一的单轮会话接缝，整个上游适配层（openai.py、chat.py、qqbot/adapter.py）即可剔除数百行泄漏的业务逻辑，并且测试重点可以直接下沉到端到端单轮执行的真实契约上。
